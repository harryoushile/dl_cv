# 第 6 课：VGG

## 这一代要解决的问题

AlexNet 的卷积核大小不统一。VGG 问：只用 3×3，把网络做成很深、又很规则的积木，精度能不能更好。

## 知识要点

- 同样的感受野，两个 3×3 比一个 5×5 参数更少。输入输出通道都是 `C` 时，两个 3×3 是 `2 * 9 * C * C`，一个 5×5 是 `25 * C * C`。
- VGG16 的卷积配置（数字是通道，`M` 是 2×2 最大池化）：

```text
64, 64, M, 128, 128, M, 256, 256, 256, M, 512, 512, 512, M, 512, 512, 512, M
```

- 每一段里高宽不变，池化时高宽减半，下一段通道常常翻倍。这个模式一直用到 ResNet。
- 2014 年的 VGG 没有 BatchNorm。例程加上 BatchNorm，是为了 CIFAR 上能和后面的 SGD 配方一起训练。原版的贡献是 3×3 堆叠和统一的通道设计。
- CIFAR 边长 32，池化 5 次后是 1×1，所以分类头是 `Linear(512, 10)`，不再使用 ImageNet 那种巨大的全连接。

## 结构与形状表

配置是 VGG11 风格的窄版本：

```text
64, M, 128, M, 256, 256, M, 512, 512, M, 512, 512, M
```

输入 `(N, 3, 32, 32)`，五次池化后：

| 阶段结束 | 空间尺寸 | 通道 |
| --- | --- | --- |
| 第一段 + M | 16 | 64 |
| 第二段 + M | 8 | 128 |
| 第三段 + M | 4 | 256 |
| 第四段 + M | 2 | 512 |
| 第五段 + M | 1 | 512 |
| Linear | 类别 | 10 |

## 对应例程导读

[code/lesson06_vgg.py](../code/lesson06_vgg.py) 用列表 `cfg` 生成层。循环里遇到 `"M"` 就追加池化，遇到数字就追加 Conv、BatchNorm、ReLU，并把 `in_ch` 更新成这一层的输出通道。

改深度时优先改 `cfg`，不要逐行复制卷积。删掉两个 512 卷积，网络仍然以 512 通道、1×1 空间结束，`Linear(512, 10)` 不用改。

## 动手实验

```bash
python code/lesson06_vgg.py
python code/lesson06_vgg.py --mode train --epochs 20
```

从 `cfg` 删掉末尾两个 512 卷积，再训练一次。比较参数量和准确率。
