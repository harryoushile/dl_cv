# 第 1 课：图像就是数组

## 这一代要解决的问题

卷积还没开始之前，先建立「图片在程序里是数字数组」这件事。形状算错，后面每一课的全连接层都会对不上。

## 知识要点

- 灰度图形状是 `(H, W)`，彩色图是 `(H, W, 3)`，像素常用 0 到 255 的整数。
- PyTorch 使用 NCHW：`(batch, channel, height, width)`。一张 MNIST 是 `(1, 28, 28)`，一个 CIFAR batch 是 `(N, 3, 32, 32)`。
- 卷积输出高宽：

```text
H_out = floor((H + 2P - K) / S) + 1
```

`K` 是卷积核边长，`P` 是 padding，`S` 是 stride。

- `kernel=3`、`padding=1`、`stride=1` 时高宽不变，只改通道。这是后面大多数网络的默认积木。
- 两个 3×3 卷积叠起来，感受野相当于一个 5×5，参数更少。第 6 课 VGG 就建立在这件事上。

## 结构与形状表

用公式手算，不写网络：

| 输入 | K, P, S | 输出高宽 |
| --- | --- | --- |
| 28×28 | 5, 0, 1 | 24×24 |
| 24×24 | 池化 2×2 | 12×12 |
| 32×32 | 3, 1, 1 | 32×32 |
| 32×32 | 池化 2×2 | 16×16 |
| 32×32 | 2, 0, 2 | 16×16 |

最后一行就是第 14 课 ConvNeXt 的 patchify stem。

## 对应例程导读

本课没有模型文件。打开 Python，确认张量维度：

```python
import torch
x = torch.zeros(4, 3, 32, 32)
print(x.shape)          # NCHW
print(x.view(4, -1).shape)  # 4 x 3072，第 2 课的线性层输入
```

`view(n, -1)` 保留 batch，把后面所有维度乘在一起。线性层要的就是这个向量。

## 动手实验

1. 手算：输入 28×28，5×5 卷积、无 padding，再 2×2 池化，再 5×5 卷积，再 2×2 池化。写出四次之后的高宽。第 4 课会用到这个结果。
2. 解释 `(8, 1, 3, 3)` 这个卷积权重形状：8 个输出通道，1 个输入通道，核是 3×3。
3. 把一张灰度图误写成 `(28, 28, 1)` 送进 `Conv2d`，预计会报形状错误。先写出错在第几个维度。

## 思考题

1. 为什么 PyTorch 把通道放在高宽前面，而很多图像库把通道放在最后？
2. padding 为 0 的 3×3 卷积，叠两层后高宽少了多少？
3. batch 是 1 和 batch 是 32，卷积核的参数量变不变？
